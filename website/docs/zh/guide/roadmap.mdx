# 路线图

本页是产品化摘要；仓库根目录的 [`ROADMAP.md`](https://github.com/A3S-Lab/Use/blob/main/ROADMAP.md) 是优先级与完成状态的唯一事实来源。

## 当前基线

截至 2026-08-04，`main` 已包含：

- schema-v3 命名 Tool Task/Service、MCP、OKF、Flow、Skill 与 UI contract；
- signed catalog v1–v3、离线验证、metadata-only search 与 planning target；
- immutable operation plan、permission ceiling、grant 与 provider evidence contract；
- exact-generation workspace grant store 和 recoverable journal；
- Runtime Task/Service binding、invocation、receipt 与 observation typed adapter；
- dependency-gated Surface Reconciler、planner evidence 和 capability snapshot；
- M0K-A `a3s.use.okf-bundle.v1` descriptor 与支持 v0.2/v0.1 的有界 inspector；
- M0K-B manifest/package validation、catalog-v3、plan-v2、manager-v2、Knowledge evidence、reconciliation 与 canonical fixtures；
- M0K-C-A 注入式 Knowledge lifecycle contract、精确字节验证、持久 last-good binding 与 package adapter；
- P0 schema-v3 package/capability host，包括 generation-bound receipt、确定性 root、原子 snapshot、route-lease drain 与精确移除。
- P0-D schema-v3 SemVer package dependency、有界解析、精确 Registry/TUF lock、signed remote CLI install/uninstall、前向闭包下载/安装、retained dependency 校验、原子图发布、durable crash replay 与反向移除。
- P0-F A3S Flow engine/runtime/source contract、Tool/MCP/OKF 依赖闭包、lifecycle/reconciler/catalog projection、真实 Native TypeScript preflight、exact-generation binding、host-capabilities v2 与 manager-toolset v3；
- 宿主持有的稳定名称 Registry 替换与启停，以及 disabled-source 过滤和内容寻址 trust-root 切换；
- A3S Code CLI/TUI/Web lifecycle-factory 组合、严格 `flow.json` 身份、单一 workspace-local 持久 runtime，以及 detached-Web 安装/运行/升级/卸载/重启覆盖。

稳定 v0.2 package foundation 仍可独立使用。上述 plugin-platform baseline 是 `main` 上的在建能力，不能被描述为完整 production plugin product。

**OKF（Open Knowledge Format）** 现已进入 schema-v3 控制面与 package-lifecycle 基线。仍需完成真实 A3S Knowledge index 后端、scope-aware capability/session projection、parent-saga cutover 与带引用检索，才能宣称 production OKF lifecycle。

## 当前关键路径

1. 在 Code Plugin Manager 已实现的 package、capability、Tool Task、stdio MCP、A3S Flow 与 static-surface 组合上，增加生产 Runtime Service、Gateway/HTTP MCP 与 Knowledge host。
2. 把 workspace-grant sub-saga 接入 package checkpoint 与 capability cutover，再让 CLI、Web、management MCP 和 managed-host mutation 统一通过该 journal。
3. 在 blue/green capability cutover 后增加旧 generation 退休，再完成 CLI/Web/Agent lifecycle 与 crash-recovery E2E。
4. 保持 Code Web/TUI 的共享 lifecycle 路径，同时让 management MCP 与 managed-host apply 通过同一个 public factory 和 package graph，再增加 retained-generation rollback 与 garbage collection。
5. 把 M0K-C-A Knowledge port 与 lifecycle adapter 接入真实 A3S Knowledge 后端和 scoped capability/session projection。
6. 增加可见 Web Flow run/history 控件，再在已完成的 workspace-local runtime 上增加分布式 worker placement、suspended work 自动恢复与生产 retention/garbage collection。
7. 每个宿主合约冻结后，再扩展 Agent、prompt、hook、memory 与 context-provider contribution。
8. 完成官方 Registry 签名/密钥运维与 Windows platform gate。

## 完成标准

认知插件平台只有在以下条件同时满足时才可宣称 production-ready：

- 同一 package identity 覆盖发现、计划、授权、安装、启用、升级、禁用与卸载；
- required Tool/MCP/OKF/Flow/Skill/UI 对同一 generation 原子可见；
- package、grant、Runtime、Gateway 和 projection 崩溃后可恢复且不会重复副作用；
- 签名目录、计划摘要、权限、provider 和 runtime observation 全链路可审计；
- CLI、Web 与 agent management MCP 共享一个 manager 和 receipt format；
- 含依赖安装在这些 adapter 间共享一个精确 lock、前向/反向生命周期与原子 capability cutover；
- Linux、macOS 与 Windows 的声明支持级别都有自动化 release gate。

## 开发原则

- 先冻结 contract 和 fixture，再实现 adapter。
- 先打通 production lifecycle，再增加新的 cognitive surface 类型。
- 不通过 fallback 掩盖 provider、权限或 readiness evidence 缺失。
- 不重复已有 manager、store、selector、registry 或 protocol。

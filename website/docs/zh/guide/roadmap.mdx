# 路线图

仓库中的 [`ROADMAP.md`](https://github.com/A3S-Lab/Use/blob/main/ROADMAP.md)
是唯一事实来源。A3S Use 尚未发布受支持的产品版本，也未达到
production-ready。合约完成和测试通过只是实现证据，不是发布声明。

## 当前协议基线

当前预览版只接受一条合约线：

| 合约                       | 当前值                                            |
| -------------------------- | ------------------------------------------------- |
| 认知包 manifest            | schema 3                                          |
| 签名 catalog               | `a3s.use.plugin-catalog.v3`                       |
| installed receipt          | schema 3                                          |
| operation plan             | `a3s.use.plugin-operation-plan.v4`                |
| host capabilities          | `a3s.use.plugin-host-capabilities.v4`，protocol 4 |
| manager MCP tools          | `a3s.use.plugin-manager-tools.v3`                 |
| pending package graph      | `a3s.use.pending-package-graph-operation.v2`      |
| enablement state/operation | v2                                                |
| OKF 内容                   | 仅 v0.2                                           |

首个受支持版本之前，过时的预览 schema、API、receipt 和磁盘状态会被删除，
不会被当作兼容目标。遇到不支持的状态时 fail closed，并提示清理后重装。
SemVer、`requires_use`、宿主 target 和 provider capability 检查仍是必须的
正确性规则。

## 已实现基线

- Manifest v3 与 catalog v3 已覆盖命名 Tool、MCP、OKF、Flow、Skill、UI
  表面、包依赖、权限上限与精确 provenance。
- 有界 resolver 会冻结一个 Registry/TUF package lock，前向准备依赖，一次
  发布图快照，再反向退休不再需要的包。
- Plan v4 分离审查和 mutation，并绑定 operation identity、confirmation、
  scope、package transition、impact、Grant、provider 与当前状态证据。
- Lifecycle journal 已提供精确崩溃重放、cutover-aware publication、精确
  generation 排空，以及 fail-closed corruption handling。
- standalone 已组合 Tool Task、stdio MCP、Skill/UI projection、SQLite/FTS5
  OKF，以及注入式 `a3s-flow` Native TypeScript preflight。
- GitHub Pages 和中英文产品文档已经存在，但只描述开发预览版。

## 剩余发布计划

### 1. 托管宿主 provider 组合 — 进行中

- 增加生产 Runtime Service 与 HTTP MCP/Gateway provider。
- 完成托管 Knowledge Workspace/session carrier 和 UI sandbox 的 ownership、
  CSP、backend binding、drain、retention 与 garbage collection。
- 证明 owner 或精确 readiness evidence 缺失时，required 表面始终不发布。

### 2. A3S Code TUI/Web 热插拔验收 — 进行中

- 让 CLI、TUI、Web、manager MCP 共用一个 Plugin Manager。
- 对全部六类表面和包含依赖的图验证 install、invoke、精确 generation
  upgrade、再次 invoke、uninstall 与 restart。
- 证明 User/Workspace scope 隔离、watcher resume、terminal result replay，
  以及崩溃后不重复副作用。

### 3. 分布式 Flow 与 OS 集成 — 待完成

- 在保持单一 package-owned `a3s-flow` 身份的前提下增加 remote placement、
  scheduling、suspension、resumption、cancellation 与 observation。
- 证明远程执行只改变 placement；唯一 lock、receipt 和 lifecycle journal
  仍由 Use 持有。

### 4. 跨平台实进程矩阵 — 待完成

- Windows x86_64 已通过真实 `a3s-use` 进程运行签名 Registry 信任/lock、
  依赖图 install/upgrade/uninstall、Grant、standalone Flow preflight/生命周期
  和 OKF cutover 场景；还会在 upgrade 完成 cutover 后杀死进程，再重放已移除
  依赖的清理，且 capability generation 不会膨胀。
- 在声明支持的 Linux、macOS、Windows target 上运行等价的签名六表面生命
  周期与故障注入场景。
- 覆盖下载中断、归档提取、cutover、drain、进程崩溃、重启、杀毒软件争用
  和 Windows reparse point。

### 5. 供应链与运维 — 待完成

- 运营一个有文档的 Registry，覆盖签名、root rotation、expiry、mirror
  replacement、offline recovery 与 incident procedure。
- 从同一 release workflow 发布可复现归档、checksum、签名、SBOM、
  provenance 和跨平台安装脚本。
- 演练存储配额/修复、备份、telemetry、安全响应与支持 runbook。

## Production-ready 定义

只有当用户可以选择可信 Registry、审查一个精确 plan、安装签名依赖图、在受
支持宿主中热使用六类表面、无需猜测地恢复、无混合 generation 地升级，并在
每个声明平台上卸载后不遗留 route、Grant、进程、projection 或包拥有状态时，
A3S Use 才可以发布。

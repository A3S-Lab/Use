# 架构

目标架构把包管理、工作负载调度与宿主渲染分开。最重要的约束是：**CLI、Web 和 Agent 管理 MCP 必须调用同一个 Plugin Manager，不得各自实现生命周期。**

```text
     local package          release bundle     named TUF registries
           └──────────────────────┬───────────────────────┘
                                  │
                    shared host Plugin Manager
       catalog · resolve · lock · policy · plan/apply · replay
                                  │ exact reviewed closure
                                  ▼
                         a3s-use package engine
    verify · install forward · bind · publish once · remove reverse
                    ┌─────────────┴─────────────┐
                    │                           │
               native plane               cognitive plane
          Runtime Task/Service       MCP · OKF · Flow · Skill · UI · context
                    │                           │
                    └─────────────┬─────────────┘
                                  ▼
                 A3S Code · Web · Knowledge · agents
```

## 所有权

| 组件                   | 拥有内容                                                                                              | 不拥有内容                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| Umbrella host          | 具名可替换 Registry 配置、trust root、启停状态、ACL policy、用户确认、secret 与 Runtime provider      | 包存储与第二套 lifecycle manager              |
| Shared Plugin Manager  | catalog、policy、plan/apply、operation replay 与父级 saga                                             | package archive 格式或 provider 内部调度      |
| A3S Use                | 包验证、不可变 generation、receipt、grant、binding evidence、route lease 与 capability reconciliation | 通用 scheduler、UI renderer 或 agent RPC 协议 |
| A3S Runtime            | Task/Service workload 与 provider capability                                                          | 包解析、信任根与用户授权                      |
| A3S Flow               | 工作流编译、持久执行、重放、存储与 observation                                                        | 包解析或并行的 `flow.json` 生命周期           |
| A3S Code/Web/Knowledge | Skill session registry、sandboxed UI、OKF registry/index 与用户体验                                   | 包安装事务与 Runtime provider 注册            |
| Package process        | 自己的 CLI、HTTP 和 MCP vocabulary                                                                    | 宿主 policy 或 ambient authority              |

## 单一事实来源

当前实现应复用下列现有模块：

- `a3s-use-core`：canonical package/plugin、dependency resolver/lock、catalog、plan、permission、grant、release 和 OKF bundle contract；
- `a3s-use-extension`：ACL manifest、package-graph Registry resolution/download、TUF catalog、package store、receipt、lease 和 workspace grant；
- `src/plugin_lifecycle`：canonical package 与 package-graph intent、依赖顺序、durable journal、coordinator，以及类型化 Tool/MCP/OKF/Flow/Skill/UI host；
- `src/plugin_runtime`：Runtime selection、binding、receipt、invocation 与 observation；
- `src/surface_reconciler` + `src/capability_registry`：依赖 readiness 和 capability publication；
- umbrella CLI 共享 Plugin Manager：唯一 lifecycle application service。

不得新增第二个 manager、grant store、Runtime selector、capability registry 或 generic execution protocol。

## 包依赖边界

Schema-v3 package 只声明 package ID 与 SemVer range；已启用的具名 Registry 集合归宿主持有。解析过程有界且确定，遇到跨 Registry 歧义会拒绝，并生成一个 canonical lock，绑定精确版本、内容摘要、宿主兼容性、Registry URL/trust root 与 TUF role version。

Operation plan 绑定该 lock。Apply 在下载 payload 前重验完整闭包，然后先准备依赖、后准备依赖者。只有已在当前 snapshot 可见的精确 locked generation 才能作为 retained dependency 复用。所有变更包通过一个 immutable snapshot 一次切换；卸载按反向顺序执行，并拒绝移除仍有已安装依赖者的包。

## Host-owned Runtime Broker

包可以声明 workload 需求，但不能选择 provider。宿主提供显式 `RuntimeClientRegistry` 和 assignment，Planner 执行两次确定性选择：

1. 在下载 archive 前，用签名 planning target 检查是否存在兼容 provider。
2. grant proposal 固定后，用相同 provider/build/capability evidence 完成最终语义选择。

任何阶段没有满足要求的 provider 都 fail closed，不得回退到 native execution 或另一个 provider。该边界已由 [ADR-001](https://github.com/A3S-Lab/Use/blob/main/docs/adr-001-plugin-runtime-broker-boundary.md) 冻结。

## 为什么使用 Saga

包存储、workspace grant、Runtime、Gateway、projection 和 capability publication 不共享数据库事务。因此完整 apply 是 durable、idempotent 的 parent saga：

```text
intent
  → package checkpoint
  → grant checkpoint
  → Runtime checkpoint
  → Gateway checkpoint
  → projection checkpoint
  → capability publication checkpoint
  → old-generation drain checkpoint
  → terminal result
```

每个 checkpoint 使用 operation ID 和 surface idempotency key。崩溃恢复从 durable intent 和最后成功 checkpoint 继续；重复 apply 返回同一 terminal result，不重复副作用。

当前 crate 内基础已在每个 package-owned surface graph 之上实现 package-lock graph：

```text
package install：  重验 lock → 前向下载/准备 package → 一次发布变更闭包
package uninstall：反向 hide/drain/remove 变更 package → 保留 retained dependency
surface enable：   前向准备 surface → 一次发布
surface disable：  hide → drain → 反向停止 surface
```

Runtime Tool/MCP、immutable Flow/Skill/UI evidence 与 OKF Knowledge adapter 已实现。P0 schema-v3 package/capability host 可把已验证 generation 提交为 installed-disabled，发布或隐藏 exact-generation snapshot，排空 route lease，并只移除 receipt-owned root。依赖基础又增加了精确 retained-node 校验、crash-safe 原子图发布、durable admission/lock record，以及 partial install/uninstall 后的 journal recovery；signed remote standalone CLI 已使用该图。A3S Code 的 Plugin Manager 现已通过 public lifecycle factory 组合 executable Tool Task、stdio MCP、真实 A3S Flow preflight host、Skill 与 UI；TUI/Web 共用一个 watcher 并热插拔精确 generation。生产 grant/Knowledge/Runtime Service/Gateway 组合、持久 Flow run routing 与旧 Runtime generation 退休仍在进行，因此该基础不代表完整 production saga 已交付。

Embedding host 实现 `CognitivePackageLifecycleFactory`，提供精确的 Runtime、Gateway、A3S Flow、Skill/UI 与 A3S Knowledge adapter，并复用 Use 的 resolver、graph journal 和 capability cutover，而不是创建另一个 package manager。standalone factory 支持 executable Task、stdio MCP 和 immutable Skill/UI projection；必需的 Service、HTTP MCP、Flow 或 OKF owner 未注入时，会在发布前失败。Code 会显式注入 Flow host，但这不会为其他 embedding 创建 fallback。

[ADR-002](https://github.com/A3S-Lab/Use/blob/main/docs/adr-002-cognitive-package-lifecycle-saga.md) 冻结了该生命周期边界。

## 运行时可见性

Surface Reconciler 观察 desired state、generation receipt、grant、binding、Runtime/Gateway health、A3S Flow observation，以及 Skill/UI/OKF projection。OKF 使用独立的 Knowledge-host owner：缺失为 pending，staged 不发布，只有精确 promoted evidence 才是 healthy。只有完整 evidence 对同一 generation 一致时，Capability Registry 才发布新 snapshot。常驻宿主可通过 generation + revision long-poll watch 热更新，无需重启。

Flow 只有一个引擎身份。Native TypeScript 是执行适配器，`flow.json` 是可视化设计/部署文档，Code 是本地宿主，OS 是远程目标。这些路径不能创建并行 package receipt 或 lifecycle journal。

OKF 的宿主边界与 Runtime 不同：它不运行进程。Use 验证并记录精确 package generation；A3S Knowledge 负责合规检查后的原子 promotion、索引与带引用检索。失败的新 OKF generation 不得替换最后一个可搜索 generation。

详细设计见 [Plugin Platform Architecture](https://github.com/A3S-Lab/Use/blob/main/docs/plugin-platform-architecture.md)。

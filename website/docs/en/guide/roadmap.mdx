# Roadmap

This page is a product summary. The repository's [`ROADMAP.md`](https://github.com/A3S-Lab/Use/blob/main/ROADMAP.md) is the source of truth for priority and completion status.

## Current baseline

As of 2026-08-04, `main` contains:

- named schema-v3 Tool Task/Service, MCP, OKF, Flow, Skill, and UI contracts;
- signed catalog v1–v3, offline verification, metadata-only search, and planning targets;
- immutable operation plan, permission ceiling, grant, and provider evidence contracts;
- exact-generation workspace grant storage and a recoverable journal;
- typed Runtime Task/Service binding, invocation, receipt, and observation adapters;
- dependency-gated Surface Reconciler, planner evidence, and capability snapshots;
- the M0K-A `a3s.use.okf-bundle.v1` descriptor and bounded v0.2/v0.1 inspector;
- M0K-B manifest/package validation, catalog-v3, plan-v2, manager-v2, Knowledge evidence, reconciliation, and canonical fixtures;
- M0K-C-A injected Knowledge lifecycle contracts, exact-byte validation, durable last-good bindings, and package adapter; and
- P0 schema-v3 package/capability hosts with generation-bound receipts, deterministic roots, atomic snapshots, route-lease drain, and exact removal.
- P0-D schema-v3 SemVer package dependencies, bounded resolution, exact Registry/TUF lock, signed remote CLI install/uninstall, forward closure download/install, retained dependency checks, atomic graph publication, durable crash replay, and reverse removal.
- P0-F A3S Flow engine/runtime/source contracts, Tool/MCP/OKF dependency closure, lifecycle/reconciler/catalog projection, real Native TypeScript preflight, exact-generation bindings, host-capabilities v2, and manager-toolset v3;
- host-owned stable-name Registry replace and enable/disable, with disabled-source filtering and content-addressed trust-root cutover; and
- A3S Code CLI/TUI/Web lifecycle-factory composition, strict `flow.json` identity, one workspace-local durable runtime, and detached-Web install/run/upgrade/uninstall/restart coverage.

The stable v0.2 package foundation remains independently usable. The plugin-platform baseline above is in development on `main` and is not a complete production plugin product.

**OKF (Open Knowledge Format)** is now part of the schema-v3 control-plane and package-lifecycle baseline. The real A3S Knowledge index backend, scope-aware capability/session projection, parent-saga cutover, and cited retrieval must still be completed before claiming a production OKF lifecycle.

## Current critical path

1. Extend the Code Plugin Manager's implemented package, capability, Tool Task, stdio MCP, A3S Flow, and static-surface composition with production Runtime Service, Gateway/HTTP MCP, and Knowledge hosts.
2. Join the workspace-grant sub-saga to package checkpoints and capability cutover, then route CLI, Web, management MCP, and managed-host mutations through that journal.
3. Add prior-generation retirement after blue/green capability cutover, then complete CLI/Web/agent lifecycle and crash-recovery E2E.
4. Preserve the shared Code Web/TUI lifecycle path while routing management MCP and managed-host apply through the same public factory and package graph, then add retained-generation rollback and garbage collection.
5. Connect the M0K-C-A Knowledge port and lifecycle adapter to the real A3S Knowledge backend and scoped capability/session projection.
6. Add visible Web Flow run/history controls, then extend the completed workspace-local runtime with distributed worker placement, automatic suspended-work resumption, and production retention/garbage collection.
7. Extend Agent, prompt, hook, memory, and context-provider contributions only after each host contract is frozen.
8. Complete official Registry signing/key operations and Windows platform gates.

## Completion definition

The cognitive plugin platform is production-ready only when all of these are true:

- one package identity covers discovery, planning, authorization, install, enable, upgrade, disable, and uninstall;
- required Tool/MCP/OKF/Flow/Skill/UI surfaces become visible atomically for one generation;
- package, grant, Runtime, Gateway, and projection recover after crashes without duplicate side effects;
- signed catalog, plan digest, permission, provider, and runtime observations are auditable end to end;
- CLI, Web, and agent management MCP share one manager and receipt format;
- dependency-bearing installs share one exact lock, forward/reverse lifecycle, and atomic capability cutover across those adapters;
- Linux, macOS, and Windows support claims have automated release gates.

## Development principles

- Freeze contracts and fixtures before implementing adapters.
- Complete the production lifecycle before adding new cognitive surface types.
- Do not hide missing provider, authorization, or readiness evidence with fallback.
- Do not duplicate an existing manager, store, selector, registry, or protocol.

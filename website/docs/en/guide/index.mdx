# Getting Started

A3S Use is the **AI Native Package Manager** for the A3S ecosystem. It does not replace `apt`, Homebrew, or WinGet. It manages native tools and cognitive plugins that participate in the A3S capability and security model.

## What is available now

| Capability                                                            | Status                                                        |
| --------------------------------------------------------------------- | ------------------------------------------------------------- |
| Local directories and bounded archives                                | Available in v0.2                                             |
| Digest-reviewed releases and TUF registries                           | Available in v0.2                                             |
| Named registry replace, enable, disable, remove, and refresh          | Available through the umbrella host                           |
| Native CLI, standard MCP, and content-bound Skills                    | Available in v0.2                                             |
| Schema-v3 Tool, MCP, OKF, Flow, Skill, and UI contracts               | Control-plane baseline implemented on `main`                  |
| Schema-v3 SemVer dependency resolver, exact lock, and graph lifecycle | Available for signed remote standalone CLI installs           |
| Schema-v3 package commit/remove and capability publish/hide/drain     | P0 generation-bound hosts implemented                         |
| OKF (Open Knowledge Format) knowledge surface                         | M0K-C-A lifecycle adapter ready; production backend pending   |
| A3S Flow workflow surface                                             | Code CLI/TUI/Web local durable runtime and hot-plug E2E ready |
| Complete Plugin Manager apply saga and production product integration | In development                                                |

The cognitive plugin contracts, dependency resolver/lock/graph coordinator, and P0 package/capability hosts are on `main`. Signed remote schema-v3 records enter that graph from both `a3s-use install` and compatible remote `component install`. The umbrella host provides stable-name Registry replace and enable/disable, while A3S Code composes the real Flow preflight host, resolves exact `flow.json` identities, and shares one workspace-local durable runtime across CLI, TUI, and Web. Production grant/Knowledge/Service/Gateway composition, distributed Flow scheduling/resumption, retention, and prior-generation retirement are still converging. An OKF surface remains unpublished without exact promoted Knowledge evidence. Use the [roadmap](./roadmap) as the source of truth before production deployment.

## Install a release

Install the complete, verified release through the A3S CLI:

```bash
a3s install use --source release
a3s use doctor --json
a3s use capabilities --json
```

Prebuilt archives are also published on [GitHub Releases](https://github.com/A3S-Lab/Use/releases). Keep each archive's binary, Skills, Dashboard, model assets, licenses, and provenance files together. Copying the facade binary alone does not preserve the complete product surface.

## Try built-in capabilities

Render a web page to a local file:

```bash
a3s use browser render https://example.com --output page.html
```

Run local OCR and return JSON:

```bash
a3s use ocr extract ./scan.png --json
```

Inspect the immutable capability snapshot:

```bash
a3s-use capability snapshot --json
```

## Install a cognitive package

Use the umbrella Plugin Manager for the reviewed user lifecycle:

```bash
a3s plugin search research
a3s plugin inspect acme/research
a3s plugin install acme/research --channel stable
a3s plugin upgrade acme/research
a3s plugin uninstall acme/research
```

The standalone engine can also install one signed package and its complete
SemVer dependency closure from an explicit host-selected Registry:

```bash
a3s-use install acme/research \
  --registry-name packages \
  --registry-url https://packages.example.org/a3s/ \
  --trust-root sha256:<64-hex-digits> \
  --version 2.0.0 \
  --json

a3s-use uninstall acme/research --json
```

Add `--package-lock-digest sha256:<64-hex-digits>` when applying a separately
reviewed resolution. Lock drift fails before any archive download. Runtime
Service, HTTP MCP, Flow, and OKF packages require their embedding host's explicit
Runtime/Gateway, A3S Flow, or A3S Knowledge lifecycle factory.

## Build from source

Rust 1.85 or newer is required:

```bash
git clone https://github.com/A3S-Lab/Use.git
cd Use
cargo build --workspace --bins --locked
./target/debug/a3s-use doctor --json
```

Run development checks inside the Use repository:

```bash
cargo fmt --all -- --check
cargo test --workspace --all-features --locked
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
```

## Install a local package

An unsigned local directory, `.tar.gz`, `.tgz`, or `.zip` requires explicit trust:

```bash
a3s-use component install acme/calendar \
  --from ./calendar-package \
  --allow-unsigned \
  --json

a3s-use component status calendar --json
a3s-use extension disable acme/calendar --json
a3s-use extension enable acme/calendar --json
a3s-use component uninstall calendar --json
```

The package ID is the stable lifecycle identity; a route is only a presentation and dispatch alias. A3S Use preserves native `argv`, stdin, stdout, stderr, exit status, and standard MCP. It does not add a universal action envelope.
